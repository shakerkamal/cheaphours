# Reliability catalogue

Every row of the reliability table in *CheapHours: System Design* and the automated tests that prove it. A
test is named `Class.Method`; `ReliabilityCatalogueTests` checks that each named test exists, so this page
cannot drift from the code.

The rule behind every row: the safe outcome is a charged car, and no command is lost or applied twice.

| Failure | What CheapHours does | Tests |
| --- | --- | --- |
| A vendor API is slow or down | Per-provider timeout and circuit breaker; one polling loop per provider, so other providers are untouched | `PollingBulkheadTests.A_slow_failing_vendor_does_not_delay_another_providers_polls`, `ProviderContractTests.Server_error_is_transient`, `ProviderContractTests.A_timeout_is_transient`, `WorkerPollingTests.A_vehicle_whose_vendor_stops_answering_goes_offline_after_three_intervals` |
| Vendor rate limit (`429`) | Waits for `Retry-After` when polling and when sending a command; a token bucket per account | `ProviderContractTests.Too_many_requests_is_transient_with_retry_after`, `CommandDispatcherTests.Rate_limit_with_retry_after_schedules_the_next_attempt_no_sooner` |
| OAuth token expired or revoked | One refresh and retry; on `invalid_grant` the account is marked reconnect-needed | `ProviderContractTests.Unauthorized_refreshes_once_and_retries_once`, `ProviderContractTests.A_revoked_refresh_token_fails_clearly`, `WorkerPollingTests.A_rotated_token_is_kept_across_a_worker_restart` |
| Charger drops the connection mid-command | The command stays open; the command monitor reconciles it against the device after the confirmation timeout and resends with the same key (in place of a boot-triggered reconcile, ADR-004); the gateway's precheck keeps a resend from starting twice | `CommandFaultTests.Charger_dropping_mid_command_and_reconnecting_available_charges_exactly_once`, `CommandMonitorConfirmTests.Silent_charger_gets_the_start_again_with_the_same_key_after_the_timeout`, `GatewayCommandConsumerTests.Start_delivered_twice_sends_one_remote_start`, `ChargerCallTests.Socket_closed_while_waiting_fails_the_call_as_closed` |
| Duplicate webhook delivery | The same delivery gets the same message id, and the inbox stores it once | `WebhookEndpointTests.The_same_webhook_delivered_twice_is_stored_as_one_reading` |
| Telemetry arrives out of order | Readings are stored by device time; `lastReading` only moves forward | `LastReadingTests.Shuffled_readings_leave_the_latest_as_last_reading`, `LastReadingTests.A_late_reading_does_not_replace_a_newer_one` |
| Worker crashes between saving and publishing | The command and its outbox entry are saved in one transaction; the relay publishes the entry once a worker runs | `CommandFaultTests.Command_saved_while_no_worker_runs_reaches_its_device_exactly_once_when_a_worker_starts`, `OutboxRelayTests.Entry_saved_while_no_worker_runs_is_published_once_a_worker_starts`, `CommandTransactionTests.Confirmation_that_fails_part_way_leaves_no_command_no_outbox_entry_and_no_plan_change` |
| RabbitMQ is down | Commands are accepted into the outbox; the relay backs off and publishes them once the broker is back | `CommandFaultTests.Three_commands_accepted_while_the_broker_is_down_each_reach_their_device_once`, `OutboxRelayTests.Entries_wait_while_the_broker_is_down_and_are_published_once_when_it_is_back`, `WebhookEndpointTests.A_verified_webhook_while_the_broker_is_down_gets_503_so_the_vendor_retries` |
| A message keeps failing | Three retries with backoff, then the dead-letter queue; a command whose dispatch keeps failing is dead-lettered after three re-announcements | `ConsumerRetryTests.A_message_that_always_fails_is_attempted_four_times_then_dead_lettered`, `CommandMonitorDispatchTests.Command_whose_handling_keeps_failing_parks_its_message_and_is_dead_lettered`, `CommandDispatcherTests.Sixth_transient_failure_dead_letters_with_the_last_failure_as_reason` |
| A command message is lost or repeated | A lost message is announced again; a repeated one meets the dispatcher's claim and acts once | `CommandMonitorDispatchTests.Lost_request_is_announced_again_and_the_command_reaches_its_device_once`, `CommandDispatcherTests.Same_request_delivered_twice_or_concurrently_sends_once`, `CommandResultConsumerTests.Duplicate_result_records_one_sent_entry` |
| Tomorrow's prices never arrive | Hourly retries until 20:00 Berlin, then one warning; the planner falls back to the earliest unpriced slots and flags the plan's prices as incomplete | `PriceImportJobTests.Prices_never_arriving_give_one_warning_and_no_request_after_eight_pm`, `GreedyPlannerTests.Too_few_priced_slots_take_the_earliest_unpriced_and_flag_incomplete_prices` |
| Daylight-saving change | Everything is stored in UTC; slot maths never assumes 96 slots | `BerlinTimeTests.Spring_change_day_has_92_slots`, `BerlinTimeTests.Autumn_change_day_has_100_slots`, `GreedyPlannerTests.Night_across_the_autumn_change_holds_36_slots` |
| Gateway is redeployed | Graceful shutdown closes sockets with 1001 and clears the registry; readiness fails while draining; the replica stops consuming its command queue. The rolling update in a cluster is tested in Phase 7 (Helm); today's tests cover one replica's shutdown | `GatewayShutdownTests.Stop_closes_every_connection_with_1001_and_clears_the_registry_without_marking_offline`, `GatewayShutdownTests.While_draining_upgrades_get_503_and_readiness_fails` |
